**Honest reading.** On small tasks that every model already solves bare, the full

extra actions. Where the toolset could *pay* is explicitly **not measured here**:

through cache reads (real-session cache hit is 96–98%, see Adoption below), and the
failure modes hooks prevent (a benchmark that never greps a 10 MB file pays the guard's
cost and collects none of its benefit).

## Per-tool impact (ablation: full minus the tool, vs full)

Each tool measured in the regime where it plausibly acts (per
[`plans/benchmarks-impact/00-INDEX.md`](../plans/benchmarks-impact/00-INDEX.md));
the other regime is **unmeasured**. Δ is "remove the tool" vs `full` — so a
**negative Δ means the tool was costing** that much, a **positive Δ means it was
saving**.

### lean-ctx (MCP + Read/Grep redirect) — easy tier; hard tier unmeasured

|---|---|---|---|---|---|
| haiku | +11% (38.4→42.8s) | 5→8 | +33% | +14% | removing it HURTS — lean-ctx saves haiku turns/reads |

Split verdict: the compression stack earns its keep on the cheap/mid tiers and is
net weight on opus for tasks this small.

## Method

- **Isolated arms** (new in this wave): every arm renders its own
  `CLAUDE_CONFIG_DIR` — `bare` via `render_bare_control()`, the rest via
  `render_full_variant()` (`evals/lib/render_config.py`) with named exclusions; MCP
  servers load via `claude --mcp-config <arm's file> --strict-mcp-config`, so ambient
  user-scope servers never leak in and the live `~/.claude` is untouched (verified by
  mtime before/after all 81 runs).
- **Fidelity note**: the isolated full arm differs from a live machine in exactly one
  way — MCP comes from `--mcp-config` instead of `~/.claude.json` user scope.
- n=3 medians with per-rep [min..max]; errored reps excluded from medians (6/87
  attempts: one OAuth-expiry batch and two transient 403s); affected cells were
  re-run as separate per-model invocations, each snapshotting fresh credentials (a
  single long invocation snapshots once up front, and arms mode now fail-fasts on a
  systemic auth failure).
- Models: `claude-haiku-4-5-20251001`, `claude-sonnet-5`, `claude-opus-4-8`
  (2026-07-02). Runner: `evals/swe_bench.py --arms … --reps 3`.
- **Limitations**: two small synthetic Go tasks in one tiny repo; single sessions of
  20–120 s (no cache-amortization regime); correctness saturated at 100% so only
  costs are measurable; ablations cover one tier per tool; n=3 is above the repo's
  own measured noise floor for direction, not for precise magnitudes — read the
  spreads.
