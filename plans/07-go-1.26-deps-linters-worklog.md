## Step 1 — Go 1.26

**What.** Bumped the `go` directive in `go.mod` from `1.23` to `1.26`. The local
toolchain used to verify is `go1.26.3`. No source changes were required.

**Why.** The repo targets the current Go release line. Moving the language version
to 1.26 unlocks the 1.22+ semantics that the linter gate then *enforces* in Step 3
— in particular `copyloopvar` (per-iteration loop variables, so redundant `v := v`
copies are flagged) and `intrange` (range-over-int). Pinning the directive first
means those linters are correct rather than aspirational.

**Verification.** `go build ./...`, `go vet ./...`, and `go test ./...` all green on
go1.26.3.

## Step 3 — Strict golangci-lint v2 gate

**What.** Added `.golangci.yml` (golangci-lint **v2** schema), wired `make fmt` and
`make lint` to it, and made the existing code lint-clean. The local linter is
`golangci-lint v2.12.2`.

The gate is intentionally strict but legible: linters are grouped in the config by
*intent* (correctness, security, idiom/consistency, complexity) so the rationale for
each is visible at the point of enabling it. Tests relax the noisier style and
complexity linters while keeping every correctness linter active.

### Why golangci-lint v2 specifically

v2 is the current schema and ships a clean split between **linting** (`run`) and
**formatting** (`fmt`). Crucially, in v2 the configured formatters (gofumpt,
goimports) are *also checked* during `run` and reported as issues when a file is
unformatted. That gives one gate two guarantees: `make lint` catches formatting
drift, and `make fmt` fixes it. The schema can be validated with
`golangci-lint config verify`, which was used while authoring the file.

### `run` settings and why

- `tests: true` — agents touch test files as much as production code, so the gate
  must cover them. (Specific noisy linters are then relaxed for `_test.go` via
  exclusions rather than skipping tests wholesale.)
- `modules-download-mode: readonly` — the lint run must not mutate `go.mod`/`go.sum`;
  if it would, that is a failure, which keeps CI hermetic and reproducible.

### Linter selection (grouped by intent)

Base set is golangci-lint's curated `default: standard` (errcheck, govet,
ineffassign, staticcheck, unused). Strictness is layered on top:

**Correctness / bug-catchers** — `asasalint`, `bidichk`, `bodyclose`,
`contextcheck`, `copyloopvar`, `durationcheck`, `errorlint`, `forcetypeassert`,
`gocheckcompilerdirectives`, `intrange`, `makezero`, `nilerr`, `nilnil`, `noctx`,
`reassign`, `rowserrcheck`, `sqlclosecheck`, `wastedassign`. These catch real
defects: unchecked type assertions that can panic (`forcetypeassert`), wrong error
wrapping/comparison (`errorlint`), returning `nil` after a non-nil error
(`nilerr`), and so on. `rowserrcheck`/`sqlclosecheck` are no-ops today (no DB code)
but are enabled so the rule is in force the moment such code lands.

**Security** — `gosec`. Common security mistakes: file permissions, subprocess
construction, weak crypto.

**Idiom / consistency** — `gocritic`, `misspell`, `nakedret`, `nolintlint`,
`perfsprint`, `predeclared`, `revive`, `testifylint`, `thelper`, `tparallel`,
`unconvert`, `unparam`, `usestdlibvars`, `whitespace`. This is the core of the
"idiomatic, consistent" requirement: `revive` (configurable golint successor),
`gocritic` (diagnostic/style/performance), and friends keep style uniform so agents
produce code that reads like the rest of the repo.

**Complexity guards** — `gocyclo` (ceiling 20) and `nestif` (ceiling 6) keep
functions from growing unreadably branchy.

### Notable settings and why

- **errcheck**: `check-type-assertions: true` (flag `x := v.(T)`, which can panic),
  but `check-blank: false`. An explicit `_ = f()` is the idiomatic Go signal for
  "deliberately ignored," used throughout for fire-and-forget writes and for
  re-unmarshaling already-validated JSON; flagging it would add noise without value.
- **govet**: `enable-all: true`, then `disable: [fieldalignment, shadow]`.
  `fieldalignment` is memory-layout micro-tuning that hurts readability here, and
  `shadow` fires on idiomatic `err` shadowing.
- **gocritic**: `enabled-tags: [diagnostic, style, performance]`.
- **gosec**: `excludes: [G104]` — unchecked errors are owned by errcheck, which
  handles them with more nuance (see `check-blank` above), so G104 would only
  duplicate-and-conflict.
- **nolintlint**: `require-explanation: true`, `require-specific: true`,
  `allow-unused: false`. Every `//nolint` must name the exact linter *and* explain
  itself, and stale directives are flagged — this keeps suppression honest and
  auditable.
- **revive**: ~18 hand-picked rules (`var-naming`, `error-strings`,
  `indent-error-flow`, `superfluous-else`, `context-as-argument`, …) covering naming,
  error conventions, and control-flow hygiene.

### Exclusions and why

- `generated: lax` and the standard presets `comments`,
  `common-false-positives`, `legacy`, `std-error-handling` filter out the usual
  well-known false positives.
- **Test files** (`_test.go`) relax `gosec`, `gocyclo`, `nestif`, `unparam`,
  `forcetypeassert`, and `noctx`: tests legitimately use magic numbers, larger table
  setups, bare type assertions on known shapes, and shell out without a context.
- A second, narrower test rule relaxes **errcheck** *only for the type-assertion
  message* (`text: Error return value is not checked$`). `forcetypeassert` is already
  relaxed in tests; errcheck's `check-type-assertions` overlaps it. Matching on that
  exact message text means unchecked *function-call* errors stay flagged everywhere
  (those read `Error return value of \`pkg.Fn\` is not checked` — different wording),
  so only the type-assertion overlap is suppressed in tests.

### Formatters and why

`gofumpt` (`extra-rules: true`) for stricter, deterministic formatting beyond gofmt,
and `goimports` with `local-prefixes: github.com/Tsurai7/agentic-cfg` so this repo's
imports are grouped and sorted last. Run with `make fmt`.

### Makefile wiring

```makefile
fmt: ## Format Go sources (gofumpt + goimports, per .golangci.yml)
	golangci-lint fmt

lint: ## Lint with golangci-lint (strict gate; see .golangci.yml)
	golangci-lint run
```

`.PHONY` already listed `fmt`/`lint`/`vet`; all other targets (`build`, `test`,
`vet`, `check`, `dry-run`, `install`, `clean`) were left untouched.

### Code changes to satisfy the new gate

The gate surfaced real findings in existing code. Each was fixed at the source where
that was the right call, and suppressed with a *specific, explained* trailing
`//nolint` only where the linter was wrong or the behavior was deliberate.

**Source fixes:**

- `internal/settings/settings.go` — gocritic `appendAssign`: rewrote to
  `kept = append(kept, fragGroups...)`.
- `internal/mcpmerge/mcpmerge_test.go` — gocritic `stringXbytes`: added the `bytes`
  import and compared with `bytes.Equal(first, second)` instead of
  `string(first) != string(second)`.
- `internal/claudemd/claudemd_test.go` — goimports: merged split import blocks.
- `internal/settings/settings_test.go` — gocritic `emptyStringTest` guard
  (`sub != "" && …`); wrapped a `json.Unmarshal` in an explicit error check for
  errcheck.
- `internal/hook/hook_test.go` — gocritic `unnamedResult`: named the two return
  values (`(decision, rewritten string)`) and kept explicit returns so `nakedret`
  stays satisfied; updated the doc comment accordingly.
- `internal/installtest/parity_test.go` — errcheck: added a `mustWrite(t, …)`
  helper and replaced all six unchecked `os.WriteFile` call-sites. The default
  `max-same-issues: 3` had originally hidden three of the six findings; the helper
  fixes all of them in one place.

**Deliberate suppressions (specific + explained trailing `//nolint`):**

- `internal/claudemd/claudemd.go` — gosec `G306`: `CLAUDE.md` is non-secret user
  config and `0644` matches the install convention, so the write keeps `0o644` with
  `//nolint:gosec`.
- `internal/mcpmerge/mcpmerge.go` — four directives: `noctx` on the synchronous
  `nodePath()` subprocess; `nilerr` on the `WalkDir` callback that intentionally
  returns `nil` on a per-entry error to keep walking; `nilerr` on the graceful skip
  in `RegisterClaudeUser` when the optional `claude` CLI is absent; and `noctx` twice
  on the `claude mcp remove` / `add-json` calls. None of these involve HTTP or a
  cancelable context — they are context-free local subprocess calls — so `noctx`/
  `nilerr` are false positives here, suppressed narrowly rather than disabled
  globally.

**Verification.** `golangci-lint config verify` accepts the schema; `make fmt` is a
no-op on the tree; `go build`, `go vet`, and `go test ./...` are green; and
`golangci-lint run ./...` reports **0 issues**.
